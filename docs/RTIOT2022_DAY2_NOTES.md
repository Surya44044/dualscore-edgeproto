# RT-IoT2022 Day 2 Notes

## Dataset Mapping
The RT-IoT2022 dataset contains 12 attack categories. To align with our research goals for robust Open-Set Recognition (OSR), we map the specific attack types into 5 generalized research categories:
- `MQTT_Publish`, `Thing_Speak`, `Wipro_bulb` -> **Benign**
- `DOS_SYN_Hping` -> **DoS**
- `ARP_poisioning` -> **ARP_Spoofing**
- `NMAP_UDP_SCAN`, `NMAP_XMAS_TREE_SCAN`, `NMAP_OS_DETECTION`, `NMAP_TCP_scan`, `NMAP_FIN_SCAN` -> **Recon**
- `DDOS_Slowloris` -> **DDoS**
- `Metasploit_Brute_Force_SSH` -> **BruteForce**

## BruteForce Exclusion
For the first real smoke test, we explicitly exclude the `BruteForce` category (`exclude_tiny_bruteforce=1`). This is because it contains only 37 samples in the entire dataset (123k rows), which is too small to reliably split into Train/Val/Test subsets and would distort statistical metrics during the initial validation of the pipeline.

## Feature Modes
Two feature modes are supported in the preprocessing script:
1. **`conservative_no_ports`**: Drops port/protocol index features (`id.orig_p`, `id.resp_p`, `proto`, `service`) and strictly utilizes traffic-statistics to prevent the model from memorizing port numbers and failing to generalize. This is the default mode for the first smoke test.
2. **`full_numeric_encoded`**: Deterministically encodes categorical features (`proto`, `service`) and retains all original numeric features. 

## Dataset Authenticity
The Day 1 baseline experiments were conducted on purely synthetic generated data to validate the training loops and memory safety without downloading large files. The Day 2 experiments utilizing `RT-IoT2022.csv` are performed on **real network traffic data**. Therefore, the metrics generated by `run_rtiot_smoke.sh` represent the first authentic evaluation of EdgeProto-OSR on real-world IoT intrusion data.
